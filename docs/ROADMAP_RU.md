### 15.10, 17:13 МСК — согласовано дополнение «Админка/VIP», работа на паузе

Владелец попросил сохранить решение в плане и приступить только после его команды. Сейчас возможностей продолжать нет. Зафиксировать план; реализацию, сборки и развёртывание не начинать до возобновления владельцем.

- В карточке выбранного сервера кнопка **«Админка/VIP»** открывает отдельное небольшое окно настроек этого сервера. Карточка — точка входа в настройки, это один согласованный вариант интерфейса.
- В окне: имя параметра **setinfo**, пароль со скрытыми символами, кнопка **«Сохранить»**. Пользователь вводит данные один раз, клиент применяет их при подключении.
- Сохранение отдельно для конкретного **IP и порта**. Пароль одного сервера не отправляется остальным; при отключении и смене сервера активный пароль предыдущего сервера не должен оставаться в отправляемом userinfo. Учесть все пути подключения.
- Это подтверждение уже имеющихся прав на игровом сервере. Пароль аккаунта CZM хранится и применяется отдельно. Полноценная консоль и произвольные команды этим дополнением не добавляются.
- Пример требуемого параметра/команды ожидается от игрока с замаскированным паролем. До начала реализации уточнить совместимость по этому примеру.

### 15.10, 19:25 МСК — работа возобновлена, «Админка/VIP»

Владелец возобновил работу. Игрок прислал пример `setinfo _pw ****`: в форме по умолчанию `_pw`. В карточке сервера добавлена кнопка, открывающая окно с параметром, скрытым паролем и сохранением. Пустой пароль удаляет настройку. Изменение применяется при следующем подключении, действующая игра не прерывается.

Хранение в приватных настройках Android, пароль зашифрован AES-GCM с привязкой к IP:порту; случайный ключ защищён Android Keystore. Минимальная версия Android остаётся прежней. Параметр — приватное поле userinfo с начальным `_`; обычные поля игрока и star-ключи не перезаписываются. Значения, способные нарушить формат протокола, отклоняются.

Секрет добавляется только в копию исходящего пакета подключения к фактическому IP:порту. Общие cvar/userinfo и конфиги его не получают. Подключение GoldSrc, современный протокол и асинхронный Steam-брокер используют этот же путь, поэтому плитка, история, прямое подключение и повторный вход не обходят привязку. Старые имена управляемых полей очищаются из копии пакета и после смены/удаления настройки. При ошибке расшифровки чужие данные не подставляются.

Проверки Java выполняют выбор между IP и портами, повторный вход, отсутствие наследования, неизменность общего userinfo, лимит пакета, недопустимые параметры, шифрование, подмену адреса, ключа и шифртекста. Тест включён в CI, патч движка добавлен отдельным `0007-czm-server-auth.patch`. Проверка выдачи прав на настоящем сервере с паролем игрока остаётся после установки готового выпуска; реальные пароли для разработки не запрашиваются.
